# CI/CD Pipeline for a News Publishing Workflow

## Week 1: Problem Definition and Scope

### Project Background
In modern software development, delivering code changes reliably and rapidly is essential. However, many legacy or manual software workflows suffer from inefficiencies that slow down the release cycle. This project simulates such an environment by introducing a rudimentary News Publishing Workflow application and establishing a modern DevOps culture around its development and deployment.

### Problem Statement
Manual news publishing workflows are error-prone and time-consuming. Deployments are often delayed due to a lack of automated testing, continuous integration, and standardized configuration management. 

### Need for the News Publishing Workflow
To properly demonstrate a DevOps pipeline, a functional but intentionally simple application is needed. The News Publishing Workflow provides a realistic scenario (content submission, review, approval) that requires moving code from a developer's workstation into a deployment/target environment consistently.

### Proposed Solution
This project addresses the inefficiencies by developing a streamlined News Publishing Workflow application integrated with a robust, automated DevOps CI/CD pipeline, establishing a reliable path from code commit to the deployment/target environment.

### Problem Scope
The primary focus of this project is the progressive implementation of DevOps practices. The scope of the application itself is constrained to a basic monolithic architecture. The project aims to implement version control, automated builds, automated UI testing (Selenium), containerization (Docker), continuous deployment (Jenkins), and configuration management (Ansible/Puppet) over a 15-week academic period.
